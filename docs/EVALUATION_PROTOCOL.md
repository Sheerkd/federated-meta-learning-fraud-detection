# Multi-seed evaluation protocol

The study compares four training methods on the same public ULB four-bank partitions: independent local models, a centralized reference, FedAvg, and first-order FedMAML. It reports both the global FedMAML initialization and one fixed personalized variant (32 training support rows, five adaptation steps). The explained personalized model is the same checkpoint and adaptation, not an additional predictive method.

Use seeds 42, 43, and 44 for model initialization and training randomness. Keep the existing mild and strong partition assignments fixed across these seeds. Thus seed variation estimates training randomness conditional on these two splits; it does not measure partition uncertainty. All methods use the same 30-input MLP, bank-specific validation thresholds, untouched bank test rows, and equal-bank macro summaries. Do not choose a method or personalization setting using test scores. The 32-row/five-step personalization setting was fixed before compiling this study; the other support-budget and step grid is exploratory.

Each method uses five training cycles: five epochs for local and centralized, five rounds with one full local epoch for FedAvg, and five rounds with one 32-support/32-query episode per bank for FedMAML. Local, centralized, and FedAvg each process approximately five times the full training rows; FedMAML deliberately uses far fewer rows to measure few-shot adaptation. The budget table must expose this difference. Cycle count and evaluation data are matched; record exposure and compute are not. Do not interpret a performance difference as an isolated effect of federation or meta-learning.

For each bank, seed, setting, and evaluation variant, save held-out rows, fraud count, prevalence, chosen validation threshold, precision, recall, F1, false-positive rate, ROC-AUC, and average precision. Calculate per-seed equal-bank macro results, then mean and sample standard deviation across the three seeds. Report the bank-level results and adaptation grid separately. No statistical significance claim is supported by three training seeds on fixed partitions.

Count model tensor bytes for training broadcasts, client updates or query gradients, and validation broadcasts. This excludes Flower transport overhead and any local compute cost. Verify each saved run and confirm explained personalized model hashes match their corresponding 32-row/five-step FedMAML results. Keep individual explanations under the bank directories; the study contains only aggregate metrics and model hashes.
